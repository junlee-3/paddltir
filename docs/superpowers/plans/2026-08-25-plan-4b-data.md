# Plan 4b — Coach App Data Layer & Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** The coach app's offline-first data layer: Codable row models mirroring the Supabase schema, a GRDB SQLite local store, mappers from DB rows to `PaddltirCore` domain types, a deliberately-simple sync engine (pull-on-foreground + outbox push + last-write-wins), a `supabase-swift` remote adapter, and async repositories the feature screens call. Everything except the live Supabase round-trip is unit-tested with no network.

**Architecture:** `apple/Sources/Data/` holds `Models/` (Codable structs per table), `Local/` (GRDB store + migrations + records), `Remote/` (a `RemoteStore` protocol + a `SupabaseRemote` adapter over supabase-swift), `Sync/` (the SyncEngine over `RemoteStore` + outbox), `Mapping/` (row → PaddltirCore), and `Repositories/` (async APIs). Feature screens depend only on repositories, never on GRDB/Supabase directly. The `RemoteStore` protocol lets the SyncEngine be tested against an in-memory fake — no network in the test suite. The one networked task uses the LOCAL Supabase stack (OrbStack + `supabase start`), and its live assertions are deferred if the stack is unavailable.

**Tech Stack:** Swift 6.2 / Xcode 26.1, GRDB.swift (SPM), supabase-swift (SPM), Swift Testing, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-08-22-paddltir-design.md` §5 (schema/RLS), the "Offline" architecture note (pull on foreground, push on change, last-write-wins on `updated_at`, no conflict engine, mirror one club's rows); roadmap `2026-08-25-plan-4-roadmap.md`. Schema authority: `supabase/migrations/*.sql` (READ these for exact columns/enums).

## Global Constraints
- **Offline model (from spec):** a local GRDB mirror of ONE club's rows; pull rows where `updated_at > last_sync` per table on foreground/launch; local writes go to an outbox and push on change; conflicts resolved last-write-wins on `updated_at`. Do NOT build a conflict-resolution engine.
- **Row models mirror the DB exactly** — column names snake_case in JSON (PostgREST) but Swift camelCase via CodingKeys; enums match the DB enums (side_pref left/right/either, gender female/male, seat_pref stroke/pace/engine/sprint/none, boat_role paddler/drummer/sweep, boat_size small/standard, crew_category open/women/mixed, session_kind training/race_day, availability_status in/out/maybe, user_role head_coach/coach/paddler, erg_source coach/self). Read `supabase/migrations/20260822000100_types_tables.sql` for the exact set.
- **Domain logic stays in PaddltirCore** — the mapping layer converts DB rows to `PaddltirCore.Paddler`/`Lineup`/`GenderRule`; it computes nothing itself beyond selecting the latest erg row.
- **No secrets committed.** Supabase URL + anon key come from an untracked `apple/Sources/App/Secrets.swift` (git-ignored) with a committed `Secrets.example.swift`; or from `Info.plist` build settings fed by env. The anon key is not a secret per se but keep it out of git anyway. The service-role key is NEVER in the app.
- Feature screens (4d–4f) will depend ONLY on the `Repositories/` async API — design those interfaces cleanly.
- `xcodegen generate` before each build. Build/test gate: `cd apple && xcodegen generate && xcodebuild -scheme Paddltir -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath DerivedData test 2>&1 | tail -20` → tests pass, BUILD SUCCEEDED.
- Commit per task with conventional prefix + Co-Authored-By / Claude-Session trailers.

```

  Models/Rows.swift            Club, Profile, PaddlerRow, ErgTest, Crew, CrewMember, SessionRow,
                               Availability, Race, Heat, SeatRow, HeatReserve, CategoryRule (Codable)

  Sync/SyncEngine.swift        pull-all + push-outbox + LWW, over RemoteStore

  App/Secrets.example.swift    committed template ; Secrets.swift is git-ignored
apple/Tests/PaddltirAppTests/  RowDecodeTests, LocalStoreTests, MappingTests, SyncEngineTests (fake remote)
```

### Task 5: Sync engine (offline, fake remote)

**Files:** `apple/Sources/Data/Remote/RemoteStore.swift`, `apple/Sources/Data/Sync/{Outbox,SyncEngine}.swift`, `apple/Tests/PaddltirAppTests/SyncEngineTests.swift`.

**Interfaces (Produces):** `protocol RemoteStore: Sendable { func pull(table: String, since: Date?) async throws -> [Data] ; func push(table: String, rows: [Data]) async throws ; var clubID: String? { get } }` (rows as raw JSON `Data` so the engine is table-agnostic; or a typed enum per table — pick one and be consistent). `SyncEngine(db: AppDatabase, remote: RemoteStore)` with `syncAll() async throws` (pull every table where `updated_at > sync_meta.last_sync`, upsert into GRDB, advance last_sync; then drain the outbox by pushing, LWW on updated_at). `Outbox.enqueue(...)`.

- [ ] **Step 1: RemoteStore protocol + a `FakeRemote`** (in the test target) holding in-memory rows with `updated_at`s, so `pull(since:)` returns only newer rows and `push` records what was sent.
- [ ] **Step 2: SyncEngine** — `syncAll`: for each table, read `last_sync`, `pull(since:)`, upsert rows (GRDB `insert(onConflict:.replace)`), set `last_sync` to the max pulled `updated_at`; then read the outbox, `push` each, clear on success. LWW: on pull, a remote row with `updated_at <= local.updated_at` does not overwrite a locally-dirtier row that's still in the outbox (simplest: outbox rows win until pushed). Keep it simple per the spec.
- [ ] **Step 3: tests (no network)** — seed FakeRemote with rows; `syncAll` pulls them into GRDB (assert counts + a value); advance FakeRemote's rows' updated_at and re-sync → only the changed rows pull; enqueue a local edit → `syncAll` pushes it (FakeRemote records it) and clears the outbox; LWW: a stale remote row does not clobber a queued local edit.
- [ ] **Step 4: build + test** → pass. **Step 5: commit** — `feat(app): offline sync engine (pull/outbox/LWW) with fake-remote tests`
